# Grounded extraction and evaluation decisions

Recorded 23 November 2026 against Anno `baecf1f4`. A caller highlighting a name needs its exact source range. A document search system needs to know which occurrences refer to the same person. A catalog consumer needs evidence for an external identifier. Anno exposes these through `Signal`, `Track` and `Identity` on `GroundedDocument`. Keeping the three questions separate lets a test identify a wrong merge even when every name is highlighted correctly. The [contract](../CONTRACT.md) defines the public behavior. The merged implementation rows below refer to that revision. Links to subsequent PRs identify follow-up fixtures or proposed changes.

Other tools expose the same interoperability problem at their API boundaries. Google's encoding parameter permits multiple offset units. Microsoft's examples show how combining marks and emoji affect indexing. An importer that accepts more than one unit should require the caller to specify it and test a non-ASCII source slice. [Google encoding reference](https://github.com/googleapis/googleapis/blob/master/google/cloud/language/v1/language_service.proto) · [Microsoft offset guidance](https://learn.microsoft.com/en-us/azure/ai-services/language-service/concepts/multilingual-emoji-support)

## Resource assumptions

Aurelius provides a concrete public Rust integration. Its language lane accepts a document budget of 2–4,096 tokens and one or two inference threads. Its manifest pins a vendored Anno dependency. The upstream fixture demonstrates an integration path. Deployment of that upstream revision and a caller latency target remain unverified. [Caller configuration](https://github.com/arlyon/aurelius/blob/1319bcdcee28ee5b668b41a2a4f85dd0722b460f/lanes/src/language.rs) · [Caller manifest](https://github.com/arlyon/aurelius/blob/1319bcdcee28ee5b668b41a2a4f85dd0722b460f/lanes/Cargo.toml)

A release-profile replay of the pinned 521-token input on one Linux logical CPU measured median warm calls of 703 ms with one ONNX encoder thread and 1,164 ms with two. Each setting had three fresh processes and five warm calls per process. The largest process peak RSS across those two settings was 498 MiB. CPU affinity and a 2 GiB virtual-address-space limit were enforced. The shared memory cgroup allowed 16 GiB. A hard 2 GiB container trial and a workload near 4,096 tokens remain open. These timings cover word-aligned inference on one synthetic input.

For publication costs, hold source byte length and existing annotation density fixed across a fixture-only process, empty response, singleton response, invalid response and successful publication. The [density benchmark](https://github.com/arclabs561/anno/pull/262) exercises the memory cost of staging a successful batch on populated documents. Measure inference separately and preserve rollback if a later cluster is invalid.

## Decisions to revisit

| Decision | Evidence required to change it |
|---|---|
| Retain the current coreference threshold. In one four-document English namesake panel, raising the antecedent margin left all held-out predictions unchanged. Both settings found 14 of 24 exact target mentions. Only eight of 26 known-distinct target pairs had both boundaries proposed exactly. | Freeze an independently labeled panel that exercises the targeted false merge, report mention-boundary misses and pair errors separately, and agree a caller latency target before selecting a new default. Multilingual benchmarking needs language-specific examples and explicit singleton and boundary policies. [CRAC shared task](https://arxiv.org/abs/2605.21369) |
| Keep linking explanations in the evaluation fixture until a producer and consumer need a new public reason type. | Demonstrate how a caller distinguishes linking disabled, unresolved local reference, resolved person outside a frozen catalog, and a known target missing from retrieved candidates. A missing catalog ID alone cannot establish which occurred. |
| Preserve document-local IDs through grounded interchange. Cross-document export needs an explicit key policy. | Exercise the actual importer with two documents sharing a local ID and verify both joins and separation after serialization before extending public identity types. A separate [single-document graph regression](https://github.com/arclabs561/anno/pull/267) exercises two catalogs that use the same identifier. That exporter case can be fixed without adding a public identity type. |
| Keep robustness relative to one backend's own matched inputs and retain the absolute quality on both cohorts. | Require matched support, exclusions and underlying counts alongside relative retention. For sparsely labeled discovery panels, record which assertion kinds had support before interpreting a zero. In a [source replay](https://github.com/arclabs561/anno/pull/264), 32/32 assertions can pass while 13/29 predictions remain unassessed. Adding one spurious prediction leaves the assertion score unchanged and raises the unassessed total to 14/30. [Sparse coverage](https://github.com/arclabs561/anno/pull/266) · [Robustness reporting](https://github.com/arclabs561/anno/pull/265) |

Broader model comparisons should use a fixed span scorer across output formats and report the language, annotation policy, hardware and data-access terms. An exact-surface caller, an evaluator using head-based cluster scores and an operator with one CPU can reasonably select different systems. [Generative information extraction survey](https://arxiv.org/abs/2312.17617) · [Named entity recognition survey](https://arxiv.org/abs/2401.10825)
