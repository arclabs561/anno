# Publishing catalog corrections to a reader

When a catalog changes, a person-specific search can gain or lose a source occurrence even if the document still contains exactly the same words. We piloted a subscriber that receives a complete grounded document, runs `anno query publication`, commits the resulting changes to a local SQLite file, and opens a separate connection to query the result. The Rust and CLI contracts let the subscriber retract a previous attribution, retain the printed text, and recognize duplicate delivery. [Caller quickstart](../QUICKSTART.md#read-changes-to-a-documents-catalog-results) · [Executable subscriber](../../verification/index_consumers/congress/check_catalog_history.py)

## A late roster and an unchanged roll call

The opening House roll on January 3, 2023 contains 435 printed member rows. We hid the Clerk’s Bioguide identifiers from the matcher and retained them for scoring. The available community directory had no House terms covering that date under a half-open term policy. Roughly **2 hours 27 minutes** after the Clerk’s recorded action, the directory received its election update. Both lookup runs used the same ordered printed names and states. Clock times here come from the Clerk’s action time and Git committer time. [Clerk source](https://clerk.house.gov/evs/2023/roll001.xml) · [Directory update](https://github.com/unitedstates/congress-legislators/commit/c2bd05283e3dbf18dde3134df1710421c959a890)

| Directory and rule | Correct catalog links | Wrong | Unresolved |
|---|---:|---:|---:|
| At the January action, require a valid House term | 0 | 0 | 435 |
| Same edition, carry the last term forward, use surname and state | 356 | 1 | 78 |
| Same edition, carry forward and honor printed given names | 358 | 0 | 77 |
| After the directory update, require a valid term and honor printed given names | 430 | 0 | 5 |
| September control, same last rule on 433 rows | 430 | 0 | 3 |

Ignoring the given name assigned “Garcia, Robert” to Mike Garcia. Keeping it let the caller defer. After the update, the strict temporal rule attributed the original occurrence to Robert Garcia. An eligibility rule can still exclude a person the record genuinely mentions. One opening-day row recorded a member as *not voting* after his term had ended. Search for the person and verification of eligibility answer different questions. These two deliberately selected roll calls share 432 member IDs. [Inputs, matching rules and digests](../../verification/index_consumers/congress/rollcall-receipt.md)

The independent `unitedstates/congress` vote collector offers another concrete comparison. We ran its pinned House parser locally. On the original records it kept every supplied Clerk ID, with zero calls to name matching. Masking one identifier at a time on the January roll let its fallback recover 360 of 435 on the prior directory, then 433 after the update. It recovered all 433 on the September control. Its fallback also uses party, date, aliases and both current and historical rosters. A deliberate swap of two supplied IDs survived the unmodified parser. This control shows the difference between accepting a source's identifier and independently corroborating it. [Collector code, reproduction and results](../../verification/index_consumers/congress/collector-study.md)

We also measured local time **after the grounded input was ready**. Across 50 trials, the optimized anno CLI, a SQLite transaction, and an independent exact-name read took a median 14.82 ms and p95 60.96 ms to make the January source searchable. Publishing the correction and reading “Garcia, Robert” by his catalog ID took a median 25.98 ms and p95 76.24 ms. Each trial started two CLI processes and used a fresh SQLite file. It ended with 435 searchable names, 430 catalog bindings and zero database changes on redelivery. This was a shared x86-64 Xeon Platinum 8573C container with a four-CPU quota. Source acquisition, matching, and network delivery are outside these durations. [Benchmark and replay assertions](../../verification/index_consumers/congress/check_catalog_history.py)

## Immediate, atomic or buffered committee results

We reconstructed 80 nonempty directory publications from 132 first-parent source editions in 2021–2025. They included 724 distinct Bioguide records, 186 withdrawals from the current directory and two returns after withdrawal. A replacement of “Jim Justice” with “James C. Justice” describes an edit to the directory’s printed form. Its legal or personal significance is outside the record. [Pinned roster and field definitions](https://github.com/unitedstates/congress-legislators/blob/82b1eaccd2cad9e4172059507f5129fc513962af/README.md)

The committee workload comprises 13,142 printed assignments across 59 updates, representing 837 distinct printed-name and catalog-ID pairs. A matcher got the printed name and the chamber indicated by the committee. It had to select a unique highest-scoring roster candidate with token Jaccard similarity at least 0.5, or abstain. The IDs in the committee file were reserved for evaluation. The same public project publishes both files, and the assignments include repeated names. This measures directory lookup on structured observations. The score is a similarity, with no probability interpretation. [Replay and alternative rules](../../verification/index_consumers/congress/committee_pilot.py)

| When to present a person-specific answer | Correct | Wrong | Unresolved | Median / p95 policy-added delay |
|---|---:|---:|---:|---:|
| Use only prior directory publications | 13,080 | 0 | 62 | 0 / 0 h |
| Process both files from the same Git revision together | 13,087 | 0 | 55 | 0 / 0 h |
| Wait for the weekly cutoff | 13,087 | 0 | 55 | 27.37 / 123.67 h |

The seven improvements came from directory evidence in the **same commit**. Waiting a week bought the same assignments and added several days of delay for some readers. Batching by a shared release ID is justified here because the publisher actually supplies one. Two records with equal wall-clock timestamps alone cannot provide that guarantee. The name “Robert Menendez” occurred under different IDs for House and Senate members from New Jersey. Spelling and state alone leave that case ambiguous. [Publication-order tests](../../verification/index_consumers/congress/test_committee_pilot.py)

The local subscriber had zero staffed review seats. The strict prior rule left 62 occurrences unresolved at decision time. An oracle simulation allowed five or twenty cases at each UTC midnight. Respectively 42 or 61 of the 62 could then receive a correct available catalog assignment within a week. Both simulated queues eventually resolved 61. These are capacity bounds for an ideal operator with the right answer when a record exists. We did not observe a human cataloger’s decision time or accuracy. Under the separate literal-search measurement, five fresh SQLite databases each replayed 59 editions. The medians of their per-run median and p95 write-through-read times were 2.28 and 9.94 ms. These timings exclude matching, network and extraction. [Committee evaluator and timing code](../../verification/index_consumers/congress/committee_pilot.py)

## An actual withdrawal under an unchanged label

A March 2017 Wikidata revision records the English label “Elmer Thomas” and an explicit Bioguide assertion `T000177`. In May, the independent congressional directory removed another “Elmer Thomas” entry, `T000165`, as an apparent duplicate. A first-plus-last matcher on the two earlier records selects the withdrawn accession. The replay uses that mistaken result as a prior publication. We have no evidence that a historical subscriber made this mistake. [Wikidata revision](https://www.wikidata.org/wiki/Special:EntityData/Q1332996.json?revision=467383067) · [Directory change](https://github.com/unitedstates/congress-legislators/commit/e9032b34362da1552326dc8b6c5c0596cf74debd)

Withdrawal alone removes the old person-search hit and keeps the literal label available. A second caller accepts the separately sourced Wikidata assertion and binds only that occurrence to `T000177`. Giving both consumers the same source hash still yields two legitimate results. The required verification suite drives both policies through separate native CLI processes, checks the original quote and scope, and checks duplicate delivery. The evidence and reuse terms are pinned in the fixture. [Source manifest](../../verification/index_consumers/congress/attribution-correction.json)

## Which interface earned a place in anno?

* **A complete view and changes from a known view.** The caller declares a stream and monotone sequence. The CLI further scopes the view by document and qualified catalog selection. An explicit source-edition token can change while its bytes remain equal. An index update can change while its source edition stays fixed. A returned location and hash refer to the grounded text. The Clerk pilot's text is a newline-joined projection of printed names. Reopening the original XML also requires its receipt and a row selector.
* **A checkpoint the receiving process can check.** A changed membership carries the old row for removal and the new row for addition. The receiver compares the incoming endpoints with its stored checkpoint, applies the rows and advances the checkpoint in one transaction. A duplicate target requires no writes. A divergent predecessor needs a retained valid path or a full snapshot. The caller chooses the persistence engine. Rust callers with their own schema can construct snapshots from structured row keys and explicit JSON values. [Public API and tested Rust examples](../../crates/anno/src/publication.rs)
* **Consumer policy stays explicit.** Valid terms, quoted names, candidate retrieval, a deferral queue and confidence calibration can change independently. A catalog reference in this view records a chosen outcome. It carries neither evidence of its truth nor permission to disclose it. The caller still supplies an audience-appropriate document and stream. A change that affects evidence alone needs that evidence revision in the caller's projection if its subscribers must observe it. These experiments did not justify adding an expiry rule, probability threshold or automatic succession rule to `Identity`.

Aurelius provides an independent check on the source-anchor design. A local harness compiled its pinned source-range validator with an unrelated model type substituted. The validator accepted all 435 January and 433 September projected occurrences, rejected changed source bytes under a retained edition, and rejected a stale edition even when the text stayed identical. It validates source locations. It does not evaluate catalog attribution. No Aurelius source or model artifacts are distributed with the pilot. [Pinned downstream validator](https://github.com/arlyon/aurelius/blob/1319bcdcee28ee5b668b41a2a4f85dd0722b460f/lanes/src/language.rs)

The pilot ran the actual anno command locally and a separate pinned upstream parser as a comparator. Production rollout, service-level latency and staffed review demand require measurements at a deployment. [Reproduce the full workload](../../verification/index_consumers/congress/README.md)
