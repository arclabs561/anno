# Read the rendered page

Open the requested revision on the surface its readers use. For a GitHub README, begin on the repository landing page. For a research result, begin at the passage or figure the reader was sent. If only Markdown or an earlier screenshot is available, identify it as your source.

Read one screen at normal size before inspecting the Markdown. What can you learn here? Name the first useful result you can actually see. Follow one example from its input through its output. Notice where you have to scroll sideways, remember a distant label, or infer what a number counts.

For an Anno example, try to point from a result back to the exact words it describes. For a research claim, read the caption, column headings, units, and denominator together. Follow the evidence link if you need to distinguish a model prediction from a supplied annotation or a reported measurement from your own observation.

Look again at a narrow width. Compare the same passage at the same reading position. Inspect screenshots at native size before assembling a side-by-side view. A table can fit while a heading wraps ambiguously; an output can fit while its input is clipped. When comparing another project, identify a specific reading task its layout makes easier.

Return the most consequential observation, the visible evidence, and its effect on the reader. Include the revision, surface, and width when they matter. A clean reading is a valid finding. A request to read ends with observations; editing and publishing need a separate request.
